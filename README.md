# 피즐리 (Pizzly)

> 틈새시간을 웰니스 시간으로 바꿔주는 성장형 캐릭터 웰니스 서비스

2026 멋쟁이사자처럼 중앙해커톤 AAC(Anti-Aging Club, 웰니스 트랙) 출품작입니다.

- 🔗 라이브 데모: **https://pizzly-three.vercel.app**
- 🎬 시연 영상: [링크 추가 예정]

## 문제 정의

직장인과 학생은 하루 중 상당 시간을 화면 앞에서 보내며 눈·손목·목·어깨에 피로가 쌓입니다. 그런데
따로 시간을 내서 스트레칭이나 휴식을 챙기기는 쉽지 않습니다. 문제는 시간이 없는 게 아니라, 이미
존재하는 짧은 틈새시간(엘리베이터 대기, 버스 대기, 잠깐의 휴식 등)을 웰니스 습관으로 연결해주는
장치가 없다는 점입니다.

피즐리는 지금 쓸 수 있는 시간(1·3·5분), 현재 상황(앉음·서있음·이동 중·조용한 곳), 현재 컨디션(눈
피로·손목·목어깨·휴식)을 입력받아, 눈 건강·손목 관리·목어깨 관리·호흡휴식 4개 영역 중 지금 가장
맞는 미니 웰니스 퀘스트를 규칙 기반으로 추천합니다. 퀘스트를 완료하면 경험치와 랜덤 보상을 얻고,
그 보상으로 캐릭터 피즐리가 성장합니다. 웰니스 습관을 "해야 하는 일"이 아니라 "내 캐릭터를 키우는
루틴"으로 바꾸는 것이 핵심입니다.

## 핵심 기능

| 기능 | 설명 |
|---|---|
| 간편 로그인 | 정식 소셜 로그인 없이 준비된 테스트 계정으로 바로 시작 |
| 퀘스트 추천 | 시간·상황·컨디션 3축 입력 기반 규칙 추천, 4개 영역 총 36개 퀘스트 |
| 퀘스트 수행 | 동작 가이드를 보면서 그 자리에서 타이머(또는 횟수 카운터) 진행 |
| 성장 | 완료 시 경험치·토큰 보상, 레벨에 따라 4단계로 캐릭터 비주얼 변화 |
| 상점 | 레벨 해금형·토큰형·프리미엄 3종 카탈로그, 구매한 코스튬 캐릭터에 착용 |
| 패스 | 구독 시 랜덤 보상 상자 확률 가중 |
| 기록 | 오늘 완료·누적 퀘스트·랜덤박스·토큰 획득 히스토리 조회 |
| PWA | 홈 화면에 앱처럼 설치 가능, 모바일 접속 시 전체 화면으로 표시 |

## 데모 방법

1. https://pizzly-three.vercel.app 접속
2. 로그인 화면에서 테스트 계정 1~4 중 아무거나 선택 (회원가입 불필요)
3. 온보딩 2문항 선택 후 "잠깐, 피즐리랑!" 버튼으로 퀘스트 추천부터 체험

> 백엔드가 무료 티어(Render)라 한동안 요청이 없으면 첫 응답에 10~30초 정도 걸릴 수 있습니다.

## 기술 스택

| 영역 | 구성 |
|---|---|
| 프론트엔드 | React 18 + TypeScript + Vite + Tailwind CSS v4, PWA(vite-plugin-pwa) |
| 백엔드 | Node.js 20 + Express + TypeScript |
| DB | MySQL 8 (Prisma ORM) |
| 인증 | JWT — 사전 준비된 테스트 계정 로그인 |
| 배포 | 프론트 Vercel / 백엔드 Render / DB Railway |

## 팀

6명 — 백엔드 2명(BE1, BE2), 프론트엔드 2명(FE1, FE2), 기획 1명(PM), 디자인 1명(DS)

| 역할 | 담당 |
|---|---|
| BE1 | 캐릭터·보상 데이터 (로그인/온보딩, 홈 상태, 퀘스트 완료 기록, 보상 로직) |
| BE2 | 추천 엔진·성장·기록·PWA 인프라 (퀘스트 추천, 레벨업 로직, 기록 조회, 패스 결제 연동, 배포) |
| FE1 | 온보딩·퀘스트 수행 (로그인/온보딩 전체, 퀘스트 시간·상황·컨디션 선택~완료) |
| FE2 | 홈·성장·상점·패스·기록 |
| PM | IA/화면 흐름, 퀘스트 콘텐츠 기준, 카피, QA 시나리오 |
| DS | 디자인 시스템, 캐릭터 비주얼, PWA 아이콘/스플래시 |

## 프로젝트 구조

모노레포로 구성되어 있습니다.

```

├── apps/
│   ├── web/   # 프론트엔드 (React + Vite)
│   └── api/   # 백엔드 (Express + Prisma)
```

## 로컬에서 실행하기

```bash
npm install
cp .env.example .env   # DB 접속 정보 등 값 채워넣기

# 터미널 1
cd apps/api && npm run dev

# 터미널 2
cd apps/web && npm run dev
```

## 개발 컨벤션

### 코드 컨벤션

- 변수·함수: camelCase (예: `getQuestList`)
- 컴포넌트·클래스·타입: PascalCase (예: `QuestCard`, `PizzlyAvatar`)
- 상수: UPPER_SNAKE_CASE (예: `MAX_LEVEL`)
- 파일명: 컴포넌트는 PascalCase(`QuestCard.tsx`), 그 외는 kebab-case(`api-client.ts`)
- API 엔드포인트: 소문자 + 하이픈, 복수형 명사 (예: `/api/quests`, `/api/pizzly-status`)
- Lint/Format: ESLint(airbnb-typescript 또는 standard) + Prettier, 저장 시 자동 포맷 적용

### API 응답 포맷

공통 응답 포맷(성공):

```json
{ "success": true, "data": { }, "error": null }
```

공통 응답 포맷(실패):

```json
{ "success": false, "data": null, "error": { "code": "QUEST_001", "message": "..." } }
```

- HTTP 상태코드: 200 / 201 / 400 / 401 / 404 / 500 만 사용
- 에러코드: `{도메인}_{번호}` 형식 (예: `AUTH_001`, `QUEST_001`, `GROWTH_001`, `REWARD_001`)
- 날짜/시간: ISO 8601 (예: `2026-08-25T09:00:00+09:00`)
- 인증: `Authorization: Bearer {JWT}` 헤더. 회원가입 없이 사전 준비된 테스트 계정으로 로그인
- 타이머/진행 상태: 클라이언트에서 초단위 관리, 서버는 완료 시점 결과값만 수신(`elapsedSeconds` 등)

### Git 협업 규칙

- 브랜치: `master`(배포용, 보호) / `dev`(통합용) / `feature/{이름}-{기능}`
- 커밋: Conventional Commits (`feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:`)
- PR: 최소 1인 승인 후 머지, 평소엔 `dev`로 머지, 배포 확정 시점에만 `dev`→`master` 병합
- 머지 방식: Squash and merge

코드 컨벤션, API 응답 포맷, Git 규칙을 포함한 더 상세한 규칙(디자인 시스템, 환경변수 관리, PWA
규칙 등)은 [CLAUDE.md](./CLAUDE.md)에 정리되어 있습니다.
